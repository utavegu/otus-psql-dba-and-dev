## Общее по работе с виртуальной машиной и кластерами PostgreSQL

### Подключение к ВМ:
Подключение к моей виртуальной машине для выполнения домашних заданий:
```
ssh student@127.0.0.1 -p 2222
```
Пароль: 123 (да, не очень секурно, но я вам поаплодирую, если вы как-то сможете воспользоться этой информацией).

### Корректная остановка ВМ:
1) Посмотреть запущенные кластеры: `pg_lsclusters`
2) Остановить запущенный кластер: `sudo pg_ctlcluster 17 main stop`
3) Отключить ВМ: `sudo poweroff`

### Обмен файлами с ВМ:

Чтобы скопировать файл с моего компьютера на виртуальную машину:
```
scp -P 2222 ~/путь-на-домашней-машине/hw03/access.sql student@127.0.0.1:~/
```

Чтобы забрать файл с виртуальной машины:
```
scp -P 2222 student@127.0.0.1:~/access_result.txt ~/путь-на-домашней-машине/hw03/
```

Или можно было вот так, что означает "скопировать в текущую директорию хоста":
```
scp -P 2222 student@127.0.0.1:~/access_result.txt ./
```
(желательно сразу находиться в той директории, в которой, по итогу, эти файлы будут нужны)

Почему -P, а не -p?
В ssh порт задаётся строчной -p, а в scp - заглавной -P. Это историческая особенность, потому что строчная -p в scp уже занята (означает «preserve» - сохранять права/время файлов).

Или можно было скопировать содержимое файла вручную, раз я всё равно сижу через терминал по ssh, предварительно выведя на экран содержимоей файла:
```
cat ~/access_result.txt
```
(в терминале виртуальной машины)
